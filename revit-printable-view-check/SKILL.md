# 视图必须可打印才可导出

## R — 原文 (Reading)

> 至少必须存在一个有效的视图，并且必须是可打印的，才能导出成功。而这可可以每个视图的 CanBePrinted 属性进行检查。
>
> — 宦国胜, 第5章 5.16 导出（约p419）

---

## I — 方法论骨架 (Interpretation)

这是一条导出前的**硬前置条件**，且失败方式最恶劣——静默失败：

- Document.Export 的视图集合里，**每个视图都必须 `CanBePrinted == true`**；集合至少要有一个有效视图，导出才可能成功。
- 违反时的症状不是异常，而是**什么都没发生**：没有文件生成、没有报错信息。这在"批量导出后半夜跑"的脚本里最难排查。
- 不可打印的典型来源：模板视图、被隐藏/不适用的视图等。
- 正确姿势是前判定模式（检查能力，再操作）：组装视图集合时就过滤 `if (view.CanBePrinted) views.Add(view.Id);`，把不可打印视图剔除或记日志，而不是导出后才发现少了文件。

一句话：导出前先过 CanBePrinted 这道闸，否则失败连错误码都不给你。

## A1 — 书中的应用 (Past Application)

### 案例 1: 导出无文件无报错的排查
- **问题**: 调用导出后既没有生成文件也没有抛异常，脚本"看似成功"。
- **方法论的使用**: 反推前置条件——检查传入视图的 CanBePrinted，发现其中混入了模板/隐藏类不可打印视图。
- **结论**: 根因是视图集合未过滤，导出静默失败。
- **结果**: 加上前置过滤 `if (view.CanBePrinted) { views.Add(view.Id); document.Export(...); }` 后，导出稳定产出文件，且不可打印视图被日志记录而非吞掉。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 写批量导出脚本（DWG/DWF 等按视图导出）时，构建视图集合的阶段。
2. 用户报告"导出没生成文件也没报错"，需要定位根因。
3. 视图集合来源不可控（用户多选、图纸视图遍历），可能混入模板视图/隐藏视图。
4. 定时任务夜里批量出图，白天发现缺文件，要排查静默失败。

- "CanBePrinted / 可打印视图"
- "模板视图导不出来" / "template view not exportable"

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **组装前过滤**
   - 构建导出视图集合时逐个检查 `view.CanBePrinted`，为 true 才加入集合；为 false 的记录到日志（视图名+原因）。
   - 完成标准: 集合内所有视图 CanBePrinted == true，且有被剔除视图的清单。
   - 判停条件: 若过滤后集合为空，停下并报告"没有可导出的可打印视图"，不要调用 Export。

2. **导出后验证产物**
   - 调用 `doc.Export(...)` 后检查返回值与目标目录中文件是否存在。
   - 完成标准: 预期文件确实出现在目标路径；未出现则进入第 3 步。

3. **失败回溯**
   - 产物缺失时按序检查：视图集合是否为空/含不可打印视图 → 目标路径写权限 → 视图集合与格式重载是否匹配。
   - 完成标准: 找到静默失败根因并修复（通常回到第 1 步补过滤）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 不按视图集合导出的格式（如 SAT/ADSK 这类直接导模型）——其前置条件不同，本红线不适用。
- 用户在问打印（Plot）失败——打印作业走打印管理器，问题域不同，只有"可打印性"概念相通。
- 已确认产物存在、问题在内容映射——转 `revit-dwg-export-tables` 等下游配置 skill。

### 作者在书中警告的失败模式

- 把模板视图/隐藏视图混进导出集合——CanBePrinted 为 false，导出静默失败，无异常可捕获。
- 只断言"集合非空"不检查可打印性——集合非空但全不可打印，同样失败。
- 夜间批处理无产物校验——静默失败被当成成功，直到用户发现缺文件。

### 作者的盲点 / 时代局限

- 基于 Revit 2014：新版本部分导出路径的错误报告有改善（个别会抛异常），但"过滤 CanBePrinted"仍是稳妥做法；PDF 导出等新能力的前置条件需另行核对。
- 书中未展开"哪些视图类型天然不可打印"的完整清单，需实测归纳。

### 容易混淆的邻近方法论

- `revit-document-export-formats`（格式决策）——本 skill 是它的前置检查项，不是竞争关系而是配套。
- 各类"写前检查 IsReadOnly/StorageType"模式——同族前判定，勿把本检查误用于参数写入场景。
