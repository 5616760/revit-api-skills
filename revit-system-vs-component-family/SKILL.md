# 系统族与构件族的识别及 API 差异

## R — 原文 (Reading)

> 如果族名称以"System Family"开始，并且加载按钮被禁用，则它属于系统族。一般族实例属于构件族，名称不以"System Family"开头。例如，桌子家具的族名称为 Desk，此外，加载按钮处于启用状态。
>
> — 宦国胜, 《API开发指南 Autodesk Revit》第3章 3.2.1 识别图元（p158）

---

## I — 方法论骨架 (Interpretation)

Revit 的族分两大阵营，API 对它们的待遇完全不同：

- **系统族**：墙、楼板、屋顶、标高、尺寸标注等，随项目模板内置。**不能**加载 .rfa、**不能**用 API 编辑族文件。它的类型走专用类（WallType、FloorType……），修改走类型属性/复合结构/参数，而不是族文档。
- **构件族**：门、窗、家具等，以 .rfa 形式存在，可加载、可编辑。走 Family / FamilySymbol / LoadFamily 三元体系。

**识别规则**（UI 角度）：族名以 "System Family" 开头且"载入/加载"按钮被禁用 → 系统族；否则是构件族（如桌子 "Desk"）。

这种双轨制连 API 面都分裂：系统族用 ThermalProperties，构件族用 FamilyThermalProperties；族文件编辑能力仅限构件族。写通用过滤逻辑时，族名可能出现三种状态——"System Family" 前缀（系统族）、普通名字（构件族）、空（体量/内建），必须分别处理。

## A1 — 书中的应用 (Past Application)

### 案例 1: UI 识别规则落地
- **问题**: 拿到一个族实例，如何判断它是系统族还是构件族？
- **方法论的使用**: 用书中识别规则——族名前缀 + 加载按钮状态反推。
- **结论**: "System Family" 前缀 = 系统族；Desk 这类正常名 = 构件族。
- **结果**: 过滤逻辑能按规则分类，无需特殊 API。

### 案例 2: 墙的类型修改路径
- **问题**: 想改基本墙——能否加载/编辑它的"族文件"？
- **方法论的使用**: 系统族无 .rfa，经 WallType 类访问类型，修改走复合结构/参数。
- **结论**: 系统族不可载入也不可编辑，族文件编辑体系只服务构件族。
- **结果**: 对系统族调 LoadFamily/EditFamily 会失败——需换专用类型类路径。

### 案例 3: 族文件章节的印证
- **问题**: 第3章 3.3 族文件给出"API 不可以对系统族进行编辑"的限制。
- **方法论的使用**: 该限制与本章识别规则互相印证。
- **结论**: "能否编辑族文件"本身就是两类族的分水岭。
- **结果**: 写族编辑工具时先判族类，否则必踩坑。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **判定族类**
   - 取族名（或按类别查内置类型）。UI 依据：是否 "System Family" 前缀 + 加载按钮状态。
   - 完成标准: 明确该对象属于系统族 / 构件族 / 无族名（体量·内建）。

2. **按类选择 API 路径**
   - 系统族: 用专用类型类（WallType/FloorType 等）访问类型与参数。
   - 构件族: 走 Family/FamilySymbol/LoadFamily 三元体系。
   - 无族名: 特判跳过，勿强取 Symbol/Family。
   - 完成标准: 写出的代码路径与族类一一对应。

3. **写通用逻辑时三态处理**
   - 对"System Family"前缀 / 普通名 / 空名三种族名分别给分支。
   - 完成标准: 过滤结果中三类对象都有归属，无未分类遗漏。
   - 判停条件: 若用户要编辑系统族，直接告知不可行并转到专用类型修改路径。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已确定是构件族（门/窗/家具），直接走三元体系即可。
- 只按 Category 过滤，不涉及"族类"概念。

### 作者在书中警告的失败模式

- "API 不可以对系统族进行编辑"——对系统族调用族编辑/加载 API 必然失败。
- 体量、内建构件族名称为空，直接按前缀判断会漏判。

### 作者的盲点 / 时代局限

- 基于 Revit 2014：后续版本对类型体系有整合，但"系统族不可编辑"的约束延续至今。
- 书中以 UI 特征做识别，纯 API 场景需结合 BuiltInCategory / 类类型综合判断。

### 容易混淆的邻近方法论

- "族文件编辑"只对构件族有意义，别把系统族的类型参数修改误当成族编辑。
- 系统族与内建构件（In-Place）都不可加载，但前者有正常类型体系、后者族名空——两类别混为一谈。
