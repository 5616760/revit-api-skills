# PointCloudFilter 过滤器机制（多平面=凸集）

## R — 原文 (Reading)

> 过滤器用于限制读取点时的搜索量，同时也用于控制点云数据的显示。PointCloudFilter 可以基于平面边界集合创建。过滤器将检查某个点是否位于如同平面法线正向所示的每个输入平面的"正"面。因此，这种过滤器隐式定义一个体量，它对应所有平面的正半空间的交集。这个体量无需闭合，但它始终是个凸集。
>
> — 宦国胜, 第5章 5.10 点云 — 过滤器（约p381-382）

---

## I — 方法论骨架 (Interpretation)

点云可能包含几百万个点，全量遍历/显示不现实——`PointCloudFilter` 用来**按空间范围收敛**：只读取或显示落在某个区域的点，既限制搜索量又控制显示。

创建方式：`PointCloudFilterFactory.CreateMultiPlaneFilter(List<Plane>)`，传入一组平面。判定规则是**每个平面法线正向的正半空间**——一个点必须同时位于**所有**平面的正面才被保留。

关键的几何洞察（本书独有的数学视角）：所有正半空间的交集在数学上**必然是凸集**（convex set），而且这个体量**无需闭合**（平面不需要围成一个封闭盒子）。两个直接推论：

1. **单过滤器表达不了凹区域**：比如 L 形区域是凹的，没有任何一组有限平面能靠"正半空间交集"拼出 L 形。要选 L 形区域的点，必须**拆成多个凸子区域，分别过滤，再合并结果**。
2. **过滤与框选天然匹配**：`Selection.PickBox` 框选得到的矩形/立方体是凸的，可以直接用多平面过滤器表达——这也是工程上最常见的组合。

方法论要点：**过滤器的能力边界由凸性决定**——碰到凹区域，先做凸分解，再逐块过滤合并。

## A1 — 书中的应用 (Past Application)

### 案例 1: L 形区域能否用单个过滤器
- **问题**: V2 预测场景——想过滤出 L 形区域内的点云，能用单个多平面过滤器表达吗？
- **方法论的使用**: 用"正半空间交集=凸集"的几何原理判断。
- **结论**: 不能——L 形是凹区域，单过滤器无法表达。
- **结果**: 拆成多个凸区域分别过滤再合并，得到 L 形内的点集。

### 案例 2: 限制搜索量 + 控制显示
- **问题**: 大点云里做偏差分析，只关心某栋楼范围。
- **方法论的使用**: 按该楼范围创建多平面过滤器，配合 GetPoints(filter, ...) 使用（revit-point-cloud-api）。
- **结论**: 过滤器限制读取点时的搜索量，同时控制显示。
- **结果**: 分析只处理兴趣区内的点，性能显著提升。

### 案例 3: 与 PickBox 结合
- **问题**: 用户框选一个区域，程序要处理该区域的点云。
- **方法论的使用**: Selection.PickBox 的矩形范围直接用多平面过滤器表达。
- **结论**: 框选 → 过滤天然衔接。
- **结果**: 框选即分析范围，交互自然。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 点云太大，只想处理某区域的点（搜索/显示/分析）。
2. 用户用框选选了点云区域，程序要提取该区域点集。
3. 需要过滤出凹形区域（如 L 形走廊）的点，不确定能不能一个过滤器搞定。
4. 点云分析性能差——怀疑是全量遍历导致。

### 语言信号 (用户的话里出现这些就应激活)

- "按范围过滤点云的点" / "filter point cloud points by region"
- "多平面过滤器怎么建？" / "create a multi-plane point cloud filter"
- "只显示框选范围内的点" / "only show points inside the picked box"
- "点云过滤器为什么不能选 L 形？" / "why can't the filter express an L-shaped region"
- "凸集/正半空间交集" / "convex set, intersection of half-spaces"

### 与相邻 skill 的区分

本 skill 与 `revit-point-cloud-api` 区分：那个管创建/访问/引擎选择，本 skill 管访问时的空间过滤工具。与通用图元过滤器（ElementFilter）区分：点云过滤器是空间几何判定（点在区域内），图元过滤器是属性/类型判定——机制不同，别套用。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **确定目标区域并判断凸凹性**：画出/描述要过滤的区域；判断它是否凸（任意两点连线仍在区域内）。
   - 凸 → 直接进入步骤 2。
   - 凹 → 拆分成多个凸子区域（凸分解），逐个处理。
   - 完成标准: 区域凸凹性已判定；凹区域已分解。

2. **构造多平面过滤器**：为每个凸子区域用 `PointCloudFilterFactory.CreateMultiPlaneFilter(planes)` 建过滤器（平面法线朝内/朝目标侧）。
   - 完成标准: 每个凸区域都有对应过滤器；平面方向正确。

3. **应用过滤并合并**：
   - 把过滤器传给 GetPoints(filter, ...)（搜索/分析）或用于控制显示。
   - 凹区域场景：合并各凸子区域的过滤结果。
   - 完成标准: 得到的点集恰好落在目标区域内；性能可接受。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 不需要空间过滤（全量点云可接受）——过滤是开销也是收益，别盲目加。
- 过滤条件不是空间性的（按强度/颜色/分类筛选）——本过滤器管不了，那是数据属性过滤。

### 作者在书中警告的失败模式

- **把凹区域当凸区域用单过滤器**——过滤结果缺角/错误（L 形问题）。
- **平面法线方向搞反**——正半空间方向反了，过滤范围完全不对。
- **忘记体量无需闭合**——误以为必须围成封闭盒子，多造了不需要的平面（多余平面反而把区域切小）。

### 作者的盲点 / 时代局限

- 书基于 Revit 2014：新版点云过滤 API（如球体过滤、更丰富工厂方法）有扩展，应按当前 SDK 核对。
- 未讨论"凸分解的自动化"——对任意凹多面体做凸分解在工程上需要自己实现或借用算法库。

### 容易混淆的邻近方法论

- "多平面过滤器"（凸集语义） vs "任意边界"（直觉语义）：过滤器只能表达凸集，不能想当然。
- 点云过滤器 vs 图元过滤器：空间判定 vs 属性判定，机制不同。
