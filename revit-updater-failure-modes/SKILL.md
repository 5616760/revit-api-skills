# 更新器常见故障（无限循环、冲突编辑、中心文件）

## R — 原文 (Reading)

> "(1)无限循环。在更新器陷入无限循环事件时，Revit 将通知用户并禁用此更新器以便 Revit 会话能持续。(2)两个更新器试图编辑同一图元……则会取消更新器，显示一条错误消息，并给用户一个可以禁用此更新器的选项。"
>
> — 宦国胜，第5章 5.6.4（约p362-363）

---

## I — 方法论骨架 (Interpretation)

Revit 为 DMU 准备了三套自动保护机制，每种故障对应一种"最终用户会看到什么"。

- **故障 1：无限循环**。更新器 A 的修改又满足自己的触发条件，循环往复。Revit 检测到后**通知用户并禁用该更新器**，让会话能继续——代价是你的自动化规则被关闭，直到用户重启/重新启用。
- **故障 2：冲突编辑**。两个更新器试图编辑同一图元。Revit **取消更新器**、显示错误消息，并给用户"禁用该更新器"的选项。
- **故障 3：中心文件缺更新器**。中心文件曾被某更新器修改过，但当前本地没有这个更新器（插件未安装/版本不同）。同步时弹出任务对话框，用户可选继续或取消同步。
- **事前防御三件套**（对应三种故障）：
  1. 触发器范围精确——不监听自己会制造的变更类型（防循环）。
  2. ChangePriority 设置合理——让不同优先级的更新器错开调度（防冲突）。
  3. 逻辑幂等——重复触发不产生新变更（防循环的第二道保险）。
- 排查思路：用户报告"插件功能消失了"时，第一反应应是"更新器可能被 Revit 禁用了"。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 互相触发的两个更新器

- **问题**: 更新器 A 把墙改成触发更新器 B 的状态，B 又改墙触发 A。
- **方法论的使用**: 按故障 1 机制推导——Revit 检测到循环后通知用户并自动禁用更新器。
- **结论**: 循环的终点不是死机而是"静默失效"，用户只看到功能消失。
- **结果**: 修复方式是收窄触发器 + 幂等逻辑，从源头不进入循环。

### 案例 2: 团队成员缺插件同步中心文件

- **问题**: 甲的插件更新器修改过中心文件，乙未装该插件，同步时看到警告对话框。
- **方法论的使用**: 按故障 3 机制——任务对话框给出继续/取消选择。
- **结论**: 更新器的存在会影响所有协作者，部署要团队级统一。
- **结果**: 团队统一安装插件后警告不再出现。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户反馈"自动规则突然不生效了"——怀疑更新器被禁用。
2. 两个插件（或一个插件的两个更新器）互相干扰、报冲突错误。
3. 团队协作中，未装插件的用户同步中心文件时弹警告。

### 语言信号 (用户的话里出现这些就应激活)

- "更新器被禁用了 / updater disabled"
- "两个更新器 冲突 同一个图元"（two updaters conflict on same element）
- "同步中心文件 警告 缺少更新器"（sync warning missing updater）

### 与相邻 skill 的区分

- 与 `revit-updater-registration-triggers` 的关系：触发器配置是防御手段之一；本 skill 汇总三类故障全貌（无限循环/冲突编辑/中心文件），用于诊断而非配置。
- 与 `revit-updater-change-management` 的区别：该 skill 是开发者侧预防纪律；本 skill 是 Revit 侧故障-恢复行为手册。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **识别故障类别**
   - 对照三类故障特征（功能静默失效→循环；错误消息+禁用选项→冲突；同步时任务对话框→缺更新器）。
   - 完成标准: 明确归类并说明对应的 Revit 自动行为。

2. **定位根因**
   - 循环→检查触发器是否覆盖自己制造的变更；冲突→列出涉事更新器的目标图元交集；缺更新器→核对团队插件版本。
   - 完成标准: 找到可指认的根因，而非"重装试试"。

3. **实施防御三件套并验证**
   - 触发器收窄 + ChangePriority 调整 + 幂等守卫；重现场景验证故障不再出现。
   - 完成标准: 原故障场景下不再触发 Revit 保护机制。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 更新器根本没被注册/没触发——那是 `revit-updater-registration-triggers` 的问题，不是故障恢复。
- 普通插件异常崩溃——无 Revit 自动保护介入，与本三类故障无关。

### 作者在书中警告的失败模式

- 循环被禁用后无人察觉——功能静默失效比崩溃更隐蔽。
- 冲突时用户选择"禁用"后不再启用——自动化规则永久丢失。

### 作者的盲点 / 时代局限

- 书基于 Revit 2014；新版对循环检测报告与禁用粒度（可按更新器/按文档）有改进，但三类故障模型仍成立。

### 容易混淆的邻近方法论

- 幂等原则（`revit-updater-change-management`）：是预防循环的内因手段，与本 skill 的"外因观察"互补。
