# 功能区（Ribbon）面板布局决策

## R — 原文 (Reading)

> 面板应该有一个大按钮作为最左侧的控件。这个按钮应该是应用程序中最常访问的命令。当面板缩小时，最左边的按钮图标将代表整个面板。此按钮可能是按钮组中唯一的按钮，也可能随后跟一个小按钮组或小按钮堆。
>
> — 宦国胜, 附录 E.9.4/E.9.5（约 p469–p470）

---

## I — 方法论骨架 (Interpretation)

功能区面板的布局不是自由发挥，Autodesk 的 UI 指南给了明确的"黄金法则"：

1. **大按钮打头**：面板最左侧一个大按钮，放整个面板最常访问的命令；面板折叠缩小时，这个按钮的图标就代表整个面板——所以它必须是"门面命令"。
2. **不超过三列**：控件超过三列就用下拉按钮收纳；面板只放"启动命令"和"控制应用"的控件。
3. **管理/关于进滑出面板**：管理设置、帮助、About 这类低频功能放滑出面板（Slide-out），不占主面板。
4. **小按钮的纵向顺序**：越常用越靠下（离建模窗口近），最少用放最上面。
5. **文字规范**：标签 ≤3 个单词、≤36 字符，用 `&` 代替 `and`。
6. **Tab 归属**：图元操作类 → `Add-Ins` Tab；分析数据类 → `Analyze` Tab。

本质是"**按使用频率分配黄金位置**"：最高频 → 大按钮；次高频 → 小按钮堆；低频 → 下拉；杂务 → 滑出面板。

## A1 — 书中的应用 (Past Application)

### 案例 1: 5 命令 + 关于按钮的面板布局（附录 E.9）
- **问题**: 5 个命令按钮 + 1 个"关于"按钮，怎么摆才符合规范？
- **方法论的使用**: 最常用命令放大按钮左侧；右侧小按钮堆 2-3 个；超三列用下拉；"关于"移出主面板进滑出面板。
- **结论**: 面板不超过三列，管理/关于控件归滑出面板。
- **结果**: 布局符合官方指南，面板缩小时门面按钮仍代表整组。

### 案例 2: Slide-out 顺序约束（s1-c11）
- **问题**: 滑出面板里的控件添加有顺序讲究吗？
- **方法论的使用**: 按规范把管理/帮助/关于类控件集中到滑出面板，注意添加顺序与分组。
- **结论**: 滑出面板承载低频杂务，顺序按功能分组。
- **结果**: 面板整洁，主区只留高频命令。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 插件有 4-6 个命令，不知道面板怎么摆、要不要下拉。
2. "关于"和设置按钮不知道放哪，放主面板嫌乱。
3. 想知道自己的 Tab 应该建在 Add-Ins 还是 Analyze。
4. 面板折叠后图标不对/不美观，需要按门面按钮逻辑调整。

### 语言信号 (用户的话里出现这些就应激活)

- "面板怎么布局 / 大按钮放哪个"
- "滑出面板放什么"
- "面板超过三列了怎么办"
- "Tab 放 Add-Ins 还是 Analyze"
- "ribbon panel layout / big button / slide-out panel / max three columns / tab organization"

### 与相邻 skill 的区分

- 与 `revit-ribbon-control-types` 的区别: 本 skill 是"控件在面板上的空间分配"，control-types 是"选哪种控件"——先选类型再布布局。
- 与 `revit-command-availability` 的区别: 本 skill 管静态布局，availability 管动态可用状态，互不替代。
- 与批次9导出/链接专题的区别: 面板布局不关心命令干什么，只关心怎么呈现命令。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **盘点命令并按频率分档**
   - 完成标准: 列出全部命令，标注每个的使用频率（高/中/低/杂务），确认"最常访问命令"唯一。若频率不清，询问用户主力场景。

2. **按规则布局**
   - 完成标准: 高频命令→大按钮最左侧；次高频→小按钮堆（越常用越靠下）；超出三列的并组进下拉按钮；管理/关于/帮助→滑出面板。给出布局示意图（文字/ASCII），并核对列数 ≤3。
   - 判停条件: 若命令多于 8 个且都是高频，停——建议拆成多个面板或分 Tab，避免单面板过载。

3. **定 Tab 归属并验证**
   - 完成标准: 图元/建模操作→Add-Ins；分析/数据类→Analyze；标签文案 ≤3 词/36 字符且用 `&`。运行验证折叠态门面按钮正确。给用户附上布局决策记录（频率依据 + 落位）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 单命令插件（一个按钮）——不存在布局问题。
- 控件类型选择（下拉 vs 分割 vs 单选组）——那是 control-types。

### 作者在书中警告的失败模式

- 面板超过三列堆满按钮 → 界面拥挤，违背官方指南，小屏幕下可用性差。
- 把"关于/设置"放主面板 → 挤占高频命令位置。
- 大按钮选了低频命令 → 面板折叠后门面含义错误，用户找不到真正常用功能。

### 作者的盲点 / 时代局限

- 本书基于 Revit 2014 的 UI 指南：新版 Ribbon 支持折叠行为自定义，指南仍适用但细节（图标尺寸、文字换行）有演进。
- 指南针对英文界面（≤3 words / `&` 替代 and），中文标签的实际长度控制书未给出，需按 36 字符折算。

### 容易混淆的邻近方法论

- "面板（Panel）"vs "选项卡（Tab）"：面板是 Tab 内的一列功能区，Tab 是整个选项卡——命令多了先加面板，再考虑加 Tab。
- "大按钮（Large）"vs"小按钮（Small）"：同一命令可同时配置大/小两种显示，面板布局决定默认呈现哪种。
